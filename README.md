# WillwitcherOS Endgame

Welcome to the complete configuration for WillwitcherOS, a personalized desktop environment built on NixOS, Hyprland, and a curated set of applications. This repository contains everything needed to replicate the setup, from the NixOS flake to the custom scripts that tie it all together.

This guide serves as the definitive manual for understanding, installing, and managing this environment.

## Project Structure

The repository is organized to be managed by both Nix and standard dotfile symlinking, providing a clear and maintainable structure.

```
/
├── .config/                  # Application configurations (Hyprland, Waybar, etc.)
│   └── willwitcherOS/        # The core NixOS Flake configuration.
│       ├── flake.nix         # The main entry point for the Nix Flake.
│       ├── hosts/            # Host-specific configurations (e.g., packages, services).
│       └── themes/           # Theme definitions for various components.
├── .local/
│   └── bin/                  # All custom user scripts for power, audio, etc.
├── .themes/                  # GTK theme files.
├── Wallpapers/               # Static and live wallpapers.
└── willwitcher_os_installer  # The main installation script.
```

-   **`.config/willwitcherOS`**: This is the heart of the NixOS configuration, structured as a Flake. It defines the entire system, including packages, services, and users.
-   **`.local/bin`**: Contains all the custom shell scripts that provide quality-of-life features, such as volume control, power menus, and screen recording helpers.
-   **Other Dotfiles**: Standard configuration files for applications like `hyprland`, `waybar`, `rofi`, `wezterm`, etc., are located in `.config/`. These are typically managed via symlinking.
-   **`willwitcher_os_installer`**: A post-installation script that applies this entire configuration onto a minimal NixOS installation.

## Installation

This configuration is designed to be deployed on top of a minimal NixOS installation. The `willwitcher_os_installer` script automates the process of applying this custom configuration.

**Important Note on User Configuration:**
This entire configuration is built around a default user named `willwitcher`. When you install NixOS, you *must* create a user named `willwitcher` during the initial setup. If you install on an existing NixOS system with a different username, you will need to adjust the flake configuration as described in the "Customizing for Your User" section below.

**Prerequisites:**

1.  A functioning, minimal NixOS installation. This means you have already booted into a NixOS live ISO, partitioned your disk, formatted it, and run the standard NixOS installation (`nixos-install`).
2.  **Crucially, ensure you create a user named `willwitcher` during the initial `nixos-install` process.**
3.  The file `/etc/nixos/hardware-configuration.nix` must exist on the new system, as it is generated by the standard NixOS installer.
4.  An internet connection.

**Recommended Installation (from chroot):**

This is the safest and preferred method.

1.  **Perform a standard NixOS installation.** Follow the official NixOS documentation to partition your drives and install a minimal system. **During this process, create a user named `willwitcher`**. Do not reboot after the installation finishes.
2.  **Enter the `chroot` environment:** If you are not already in it, mount your new system's root partition to `/mnt` and run:
    ```sh
    nixos-enter
    ```
3.  **Log in as the `willwitcher` user:**
    ```sh
    su - willwitcher
    ```
4.  **Connect to the Internet** from within the chroot if you haven't already.
5.  **Run the Installer Script:**
    - Execute the following command to download and run the script. It will clone the repository, apply the full system configuration via `nixos-rebuild`, and set up the dotfiles with `stow`.
    ```sh
    curl -L https://raw.githubusercontent.com/walberh96/willwitcher-OS-Endgame/main/willwitcher_os_installer | bash
    ```
6.  **Reboot:**
    - The script will automatically reboot the system at the end. You can now log into your fully configured WillwitcherOS environment.

**Alternative Method (from a running TTY):**

You can also run the installer on an already-booted minimal NixOS system from a TTY, but this is less ideal.

1.  Log in to your minimal NixOS installation *as the `willwitcher` user*.
2.  Ensure you have an internet connection.
3.  Run the installer script as described above.
4.  The script will cause the screen to flash as it rebuilds the system and will reboot automatically.

## Managing Your System

### Customizing for Your User

If you are installing this configuration on an existing NixOS system where your username is *not* `willwitcher`, or if you wish to change the primary user, you have two options:

1.  **Change the username in the flake configuration:**
    *   First, clone this repository: `git clone https://github.com/walberh96/willwitcher-OS-Endgame.git ~/willwitcher-OS-Endgame`
    *   Navigate to the configuration: `cd ~/willwitcher-OS-Endgame/.config/willwitcherOS/hosts/desktop`
    *   Edit `configuration.nix` and `home.nix` (if present) to replace all occurrences of `willwitcher` with your desired username.
    *   Then, proceed with the installation steps from the "Alternative Method (from a running TTY)" section, making sure to run the `willwitcher_os_installer` from your current user's session.

2.  **Create the `willwitcher` user on your existing system:**
    *   You can create the `willwitcher` user and set a password using standard NixOS user management in your existing `configuration.nix`.
    *   Then, switch to the `willwitcher` user and run the `willwitcher_os_installer` from their session (e.g., in a TTY).

### Adding Packages

Packages are managed declaratively through the Nix Flake. To add a new package, you need to add it to the appropriate file in the `.config/willwitcherOS/hosts/desktop/` directory.

-   **User Packages**: For GUI applications and user-specific tools, add the package name to `user_packages.nix`.
-   **System Packages**: For system-wide services and essential command-line tools, add the package name to `system_packages.nix`.

After adding a package, apply the changes by running:
```sh
nixos-rebuild switch --flake .config/willwitcherOS#desktop --impure
```

**Why `--impure`?**
The `--impure` flag is required because the NixOS configuration imports `/etc/nixos/hardware-configuration.nix`, which is generated during installation and is external to the flake. This makes the build "impure" as it relies on an outside file.

### Updating the System

To update all packages and the system configuration, navigate to your repository directory and run:

1.  **Update the Flake Inputs:**
    ```sh
    nix flake update .config/willwitcherOS
    ```
2.  **Apply the New Configuration:**
    ```sh
    nixos-rebuild switch --flake .config/willwitcherOS#desktop --impure
    ```
3.  **Alias for Rebuilding (ww-rebuild):**
    For convenience, an alias `ww-rebuild` has been added to the Zsh configuration. You can simply run this command from anywhere in your terminal to rebuild and apply your NixOS flake configuration.
    ```sh
    ww-rebuild
    ```

## Initial Setup & Bootstrap Scripts

The first time you log in, a few scripts run automatically to configure your environment. This is handled by `exec-once` entries in the `~/.config/hypr/hyprland.conf` file.

-   **`git-bootstrap-check`**:
    - **Purpose**: Checks if `git` is configured with your name/email and if the GitHub CLI (`gh`) is authenticated.
    - **Why it runs**: If your Git identity is not set up, you won't be able to push to repositories. This script opens a terminal (`wezterm`) running `setup-git-gh` to guide you through the process interactively. This ensures your development environment is ready from the first boot.
    - **Dependencies**: `git`, `gh`, `wezterm`, `setup-git-gh`.

-   **`ww-nwg-look-init`**:
    - **Purpose**: Sets the initial GTK theme (for icons, fonts, and cursors).
    - **Why it runs**: On the first login, the GTK theme is not set. This script opens `nwg-look`, a graphical tool, allowing you to choose and apply your preferred theme. On subsequent logins, it silently applies the previously saved configuration.
    - **Dependencies**: `nwg-look`.

-   **`ww-waypaper-init`**:
    - **Purpose**: Sets the wallpaper.
    - **Why it runs**: On the first login, no wallpaper is set. This script opens the `waypaper` GUI for you to select a wallpaper. On subsequent logins, it automatically restores the last used wallpaper.
    - **Dependencies**: `waypaper`.

-   **`ww-set-default-apps`**:
    - **Purpose**: Sets default applications for common file types (e.g., browser, file manager, PDF viewer).
    - **Why it runs**: This ensures that files open with the correct, pre-configured applications from the start.
    - **Dependencies**: `xdg-mime`.

## Custom Scripts (`~/.local/bin`)

This setup includes a suite of custom scripts to manage system features. They are all located in `~/.local/bin`, which is automatically added to your `PATH`.

| Script                 | Purpose                                                                                                 | Dependencies                                                |
| ---------------------- | ------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| `git-bootstrap-check`  | Checks if `git` and `gh` are configured; launches `setup-git-gh` if not.                                  | `git`, `gh`, `wezterm`, `setup-git-gh`                        |
| `setup-git-gh`         | An interactive wizard to configure `user.name`/`user.email` and log in to GitHub via `gh auth login`.     | `git`, `gh`                                                 |
| `ww-apply-cursor`      | Reads the cursor theme from GTK settings and applies it to Hyprland. Called by `nwg-look` scripts.        | `hyprctl`                                                   |
| `ww-audio-toggle`      | Toggles mute for the default audio sink.                                                                | `wpctl` or `pactl`                                          |
| `ww-bluetooth-status`  | Provides a JSON status for the Waybar Bluetooth module.                                                 | `bluetoothctl`                                              |
| `ww-bluetooth-toggle`  | Toggles Bluetooth power on/off.                                                                         | `bluetoothctl`                                              |
| `ww-dotfiles-sync`     | Clones the dotfiles repo and uses `stow` to symlink configs. Not used in the main installation.           | `stow`, `git`, `hyprctl`                                    |
| `ww-nwg-look-gui`      | A wrapper to launch the `nwg-look` GUI and apply the selected cursor.                                     | `nwg-look`, `ww-apply-cursor`                               |
| `ww-nwg-look-init`     | Initializes the GTK theme on the first login.                                                             | `nwg-look`, `ww-apply-cursor`                               |
| `ww-power`             | Power menu script that gracefully shuts down Steam before `poweroff`, `reboot`, or `logout`.              | `systemctl`, `hyprctl`, `steam` (optional)                  |
| `ww-rec-rofi-region`   | A Rofi menu to start/stop a regional screen recording with audio options.                                 | `gpu-screen-recorder`, `rofi`, `slurp`                      |
| `ww-rec-rofi-screen`   | A Rofi menu to start/stop a full-screen recording with audio options.                                     | `gpu-screen-recorder`, `rofi`                               |
| `ww-rec-stop`          | A simple, non-interactive script to stop an active recording.                                           | `pkill`, `pgrep`                                            |
| `ww-screenrec`         | A comprehensive CLI wrapper for `gpu-screen-recorder` with many subcommands and options.                  | `gpu-screen-recorder`, `slurp` (optional)                   |

| `ww-screenrec-status`  | Provides a JSON status for the Waybar screen recording module.                                          | `pgrep`                                                     |
| `ww-set-default-apps`  | Sets default applications for various MIME types on first login.                                        | `xdg-mime`                                                  |
| `ww-volume`            | Adjusts volume with `wpctl` and shows a notification with the current level.                            | `wpctl`, `notify-send`                                      |
| `ww-waypaper-init`     | Initializes the wallpaper on the first login.                                                           | `waypaper`                                                  |
| `ww-wifi-status`       | Provides a JSON status for the Waybar Wi-Fi module.                                                     | `nmcli`                                                     |
| `ww-wifi-toggle`       | Toggles Wi-Fi power on/off.                                                                             | `nmcli`                                                     |
